INDEX: (poli_id, tanggal_antrean, status) -- untuk query papan antrean cepat
UNIQUE: (pasien_id, dokter_id, tanggal_antrean) WHERE status NOT IN ('batal') -- cegah double booking

Catatan teknis: constraint unique kondisional tidak native di MySQL. Implementasikan validasi double-booking di QueueService, bukan hanya mengandalkan DB constraint. Tambahkan unique index biasa di (pasien_id, dokter_id, tanggal_antrean) dan handle status 'batal' dengan soft-exclude di query level, ATAU gunakan generated column MySQL 8 sebagai workaround jika ingin enforce di DB.

4. STATE MACHINE STATUS ANTREAN

menunggu → dipanggil → dilayani → selesai
menunggu → batal          (dibatalkan pasien/admin sebelum dipanggil)
dipanggil → tidak_hadir   (dipanggil 3x tidak muncul, auto/manual oleh dokter)
tidak_hadir → dipanggil   (dipanggil ulang manual oleh dokter, opsional)

Aturan: transisi status TIDAK BOLEH lompat (misal menunggu langsung ke selesai). Validasi ini wajib ada di QueueService::updateStatus(), lempar exception kalau transisi tidak valid.

5. BUSINESS LOGIC DETAIL (per Service Class)

5.1 QueueService

generateNomorAntrean(Poli $poli, string $tanggal): array

Cari MAX(nomor_urut) untuk poli & tanggal tsb → +1. Kalau belum ada, mulai dari 1.

WAJIB pakai DB transaction + lockForUpdate() pada query max nomor, untuk cegah race condition kalau 2 pasien daftar bersamaan.

Return ['nomor_urut' => 7, 'kode_antrean' => 'A-007']

daftarAntrean(Pasien, Dokter, Poli, tanggal): Antrean

Validasi: jadwal dokter tersedia di hari tsb, kuota belum penuh, pasien belum punya antrean aktif (status IN menunggu,dipanggil,dilayani) untuk dokter yang sama di tanggal yang sama.

Panggil generateNomorAntrean(), simpan record, set status menunggu.

panggilBerikutnya(Dokter, tanggal): ?Antrean

Ambil antrean status menunggu dengan nomor_urut terkecil untuk dokter & tanggal tsb.

Update status → dipanggil, set jam_dipanggil = now().

Broadcast event AntreanDipanggil.

updateStatus(Antrean, string $statusBaru): void

Validasi transisi sesuai state machine di atas.

Jika selesai, set jam_selesai = now().

resetHarian() — dijalankan via scheduled command tiap tengah malam (opsional, karena nomor_urut sudah discope per tanggal_antrean, reset ini lebih untuk cleanup/arsip, bukan wajib).

5.2 NotificationService

Trigger saat panggilBerikutnya() dipanggil: kirim notifikasi ke pasien dengan nomor_urut = nomor yang baru dipanggil + 2 (early warning), dan ke pasien yang baru dipanggil (pemberitahuan giliran).

Channel: database (wajib), broadcast (untuk toast real-time di halaman pasien), mail/WhatsApp (opsional, fase 2).

5.3 Authorization Logic (Policy, bukan cuma middleware)

AntreanPolicy::call(User $user, Antrean $antrean) → true hanya jika $user->dokter->id === $antrean->dokter_id.

AntreanPolicy::cancel(User $user, Antrean $antrean) → true jika admin, ATAU pasien pemilik antrean DAN status masih menunggu.

Semua controller method sensitif WAJIB $this->authorize(), jangan andalkan middleware role saja (middleware cuma filter role umum, bukan ownership per-record).

7. STYLE GUIDE / DESIGN SYSTEM

7.1 Prinsip

Desain harus fungsional dan jelas dibaca dari jarak jauh (khususnya papan antrean, akan ditampilkan di TV/monitor rumah sakit). Hindari desain yang terlalu ramai/dekoratif untuk konteks medis — prioritaskan clarity, bukan estetika trendi.

7.2 Palet Warna (Tailwind config custom)

primary:    #0F766E  (teal-700)  -- header, tombol utama, identitas RS (kesan medis, tenang)

success:    #16A34A  (green-600) -- status selesai

7.4 Tipografi

Font: Inter (via Google Fonts, atau font-sans default Tailwind sudah cukup)

Papan antrean (display board): ukuran nomor antrean minimal text-8xl sampai text-9xl, bold, kontras tinggi — ini yang dibaca dari jarak 5-10 meter.

Dashboard admin/dokter: text-sm/text-base standar, densitas informasi lebih tinggi karena dilihat dari dekat.

7.5 Layout per Role

Admin: sidebar layout (menu kiri fixed: Dashboard, Poli, Dokter, Jadwal, Laporan), konten kanan dengan tabel + pagination standar (gunakan komponen tabel reusable <x-table>).

Dokter: layout minim distraksi, fokus 1 panel besar berisi antrean saat ini + tombol aksi besar ("Panggil Berikutnya" harus jadi tombol paling dominan di layar, ukuran besar, mudah diklik tanpa presisi tinggi — dokter sering pakai ini sambil kerja cepat).

Pasien: layout mobile-first (kemungkinan besar diakses dari HP), card-based, bottom navigation jika perlu.

Papan Antrean (publik): full-screen, tanpa navigasi/header standar, auto-refresh, didesain untuk TV landscape.

7.6 Komponen Reusable (Blade Component)

Buat di resources/views/components/:

<x-status-badge :status="$antrean->status" />

<x-table :headers="[...]">...</x-table>

<x-button variant="primary|secondary|danger" size="sm|md|lg">

<x-card>

<x-empty-state message="Belum ada antrean hari ini" />

7.7 Aksesibilitas & UX kecil yang penting di konteks RS

Semua tombol aksi kritikal (Panggil, Selesai, Batal) harus ada konfirmasi (modal/alert) sebelum eksekusi — kesalahan klik di alur medis berdampak nyata.

Kontras warna WCAG AA minimum, terutama papan antrean (dibaca lansia).

Ukuran font dasar jangan di bawah text-sm (14px) di seluruh aplikasi.
